Understanding the World Wide Web

An educational guide covering core internet architectures, networking concepts, and communication protocols.

1. Internet Overview

The Internet is a global, physical infrastructure consisting of interconnected computers, fiber-optic cables, routers, satellites, and copper wires. It serves as the physical communication highway that allows devices to share data across the globe.

The World Wide Web (WWW), on the other hand, is an information system built on top of the Internet. Created by Sir Tim Berners-Lee in 1989, the Web consists of digital documents, media, and websites connected by hyperlinks. Users retrieve these pages using web browser applications.

Key Difference: Think of the Internet as the physical rail tracks, and the Web as the trains running on them carrying passengers and goods.

2. Fundamental Computer Network Concepts

Understanding the fundamental concepts used to manage data traffic over networks:

IP Address

A unique numerical address assigned to every device on a network (like 192.168.1.1). It tells routers where data is coming from and where it is going.

Packets

Instead of sending large files all at once, data is chopped into smaller chunks called packets. Packets are transmitted independently and reassembled at their destination.

Protocols

Standardized sets of rules that define how data is prepared, routed, and processed between computers (e.g. TCP, IP, HTTP, and HTTPS).

Client-Server Model

A model where clients (like web browsers) request resources, and servers (powerful computers listening on the network) respond by sending those resources.

3. URL and its Structure

A URL (Uniform Resource Locator) is the specific web address used to find resources on the Web. The diagram below details the components that make up a typical URL:

  • Protocol (https://): Specifies the set of rules the browser uses to download files securely.
  • Domain Name (www.example.com): The human-friendly address identifying the server computer hosting the site.
  • Path (/courses/web-dev): The folder structure indicating the location of the resource on the server.
  • Query String (?session=fall): Optional parameters passing specific data to server scripts (separated by & if multiple).

4. Domain Name

A Domain Name is a human-readable text address that makes it easy for us to visit websites. Because computers communicate using numbers (IP Addresses), the web uses the Domain Name System (DNS) to look up domain names and translate them back into their numeric IPs.

Domain Hierarchy: Domains are structured in tiers:

  • Top-Level Domain (TLD): The ending extension of the domain, representing its category or location. Examples: .com (commercial), .org (organizations), .edu (educational), and country codes like .in or .uk.
  • Second-Level Domain (SLD): The unique name directly preceding the TLD. In google.com, google is the Second-Level Domain.
  • Subdomain: Precedes the SLD to specify a sub-resource. In blog.example.com, blog is the subdomain.

5. Web Browsers vs Web Servers

The client-server relationship is driven by two main pieces of software:

Web Browser (Client-Side)

A web browser is software installed on the user's computer that fetches, parses, and displays files from web servers.

  • Main Job: Requests HTML/CSS/JS and renders them visually for users.
  • Execution: Runs scripts locally on the user's CPU and RAM.
  • Examples: Google Chrome, Mozilla Firefox, Safari, Microsoft Edge.

Web Server (Server-Side)

A web server is a program running on a remote computer that stores site assets and listens for incoming browser requests.

  • Main Job: Accepts requests, processes logic, retrieves database records, and sends files back.
  • Execution: Runs scripts on remote server machines.
  • Examples: Apache, Nginx, Microsoft IIS, Node.js (Express).

6. Working Principle of a Website

Whenever you navigate to a page, a standard series of communication steps occur. Below is the request-response lifecycle mapping this transaction:

  1. DNS Lookup: You type the domain name. The browser sends a DNS Request to the DNS server to find the matching IP address.
  2. IP Returned: The DNS server replies with the IP address.
  3. HTTP Request: The browser connects directly to that IP address and sends an HTTP Request (like GET) to the Web Server, asking for the webpage files.
  4. HTTP Response: The Web Server processes the request and sends an HTTP Response back containing the webpage files (HTML, CSS, JavaScript). The browser reads the files and renders the website on your screen.

7. Client-side vs Server-side Scripting

Webpages often require scripts (programs) to perform actions. These scripts can run on either the client browser or the remote web server:

Comparison Aspect Client-Side Scripting Server-Side Scripting
Execution Location Runs locally inside the user's web browser. Runs remotely on the web server.
Common Languages JavaScript, HTML, CSS. Node.js, PHP, Python, Java, Ruby, ASP.NET.
Database Access Cannot access database directly (requires calling APIs securely). Can connect directly to server databases (e.g. MySQL, MongoDB).
Security Source code is public; visible via "View Source" in the browser. Source code is secure and private on the server (only the output is sent).
Main Purpose User interfaces, client validations, and slide-in animations. User accounts, processing payments, and dynamic HTML generation.
